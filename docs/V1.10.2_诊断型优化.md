# V1.10.2 诊断型优化说明

## 目的
在现有 V1.10（105份上游规则、22,019条聚合规则）的基础上增加静态诊断报告，不更改已通过真机测试的分流规则、策略顺序、TikTok、Advertising 或 MITM。

## 新增文件
- `rule_types.md`：规则类型数量及占比。
- `domain_overlap.csv`：HOST/HOST-SUFFIX 的上级域名覆盖、关键词及通配符对已枚举域名的潜在交叉。
- `ip_overlap.csv`：IPv4/IPv6 CIDR 网段潜在交集。
- `priority_audit.md`、`priority_audit.json`：P1/P2 分级和来源、位置等证据。
- `rule_analysis_diff.md`：根据上一次已发布的 JSON 指纹做增删候选数比较；首次构建无历史基线。

## 分类与局限
- P1：跨策略候选中含 direct/reject，需优先人工复核，并非确定误分流。
- P2：不同代理策略的静态交叉，常见于正常的专项覆盖。
- 不能模拟 Quantumult X 匹配优化的真实命中；不计入前置 Advertising、独立 TikTok、本地规则和真实 DNS/节点状态。
- 通配符基于 fnmatch 近似，关键词只检查已枚举域名；CIDR 重叠可能是共享 CDN 的正常现象。
- 分析器只生成报告，不会删除、调整或覆盖已发布规则。

## 部署
先检查 PR 自动测试，合并后在 Actions 手动运行「更新 Quantumult X V1.10 扩展规则（稳定）」，核查 `reports/v1.10/` 是否生成上述报告。诊断步骤设置为 `continue-on-error: true`：报告生成失败会在日志中显示，但不会使原 V1.10 安全审计之外的流程被新增条件阻止。

手机端不必更新配置，也不要将 MITM 私钥、订阅链接或节点凭据上传到公开仓库。
