# Quantumult X V1.10.1 稳定性优化

本次升级仅修改公开 GitHub 规则生成、诊断与持续集成流程，**不修改 V1.10 已经真机验收的 .list 规则、节点配置、广告策略、TikTok、MITM 或订阅**。

## 主要改动

1. `.github/workflows/update-v110.yml` 增加 GitHub Actions 定时更新：UTC 03:17（北京时间 11:17），每月日期 1、4、7...运行，接近每三天一次；月末并非严格72小时。保留手动触发及人工批准策略变更选项。
2. 新增 `scripts/conflict_review_v110.py`：利用原有聚合器 `summary.json` 生成 `reports/v1.10/conflict_review.md` 和 `conflict_review.json`，按直连与代理重叠、拦截与放行重叠、不同代理策略重叠分类，输出来源组合排名及复核样例。
3. 新增 `tests/test_conflict_review_v110.py`：测试分类、重复选择器去重统计、可重复构建、异常输入拒绝处理。
4. 新增 `.github/workflows/validate-v110.yml`：针对 PR 自动运行离线回归测试和现有报告检查，使用只读权限。
5. 原有下载失败不发布、SHA校验、危险规则拒绝、变化阈值审计、Git rebase 与非强制推送保护不变。

## 发布与验收

先合并本 PR，再在默认分支手动触发 `更新 Quantumult X V1.10 扩展规则（稳定）` 工作流一次：

- 单元测试全部通过；
- `reports/v1.10/conflict_review.md` 成功生成；
- `reports/v1.10/audit.md` 继续通过安全审计；
- `rules/v1.10/BeforeTikTok.list` 和 `AfterTikTok.list` 不因本次维护而发生策略变化。

之后自动按照计划检查上游变化。如果没有实质变化，不会生成无意义提交。

## 检查范围与局限

报告中的539为**精确匹配条件的跨策略重叠记录**，并非539个故障，也未必是539个不同域名。脚本不能判断不同 HOST/HOST-SUFFIX/KEYWORD、IP 网段的包含关系，也不包含前置 Advertising、独立 TikTok 或用户自定义 filter_local 的优先级。诊断报告不会自动删改规则。

手机端继续使用 V1.10 现有配置与原有两条规则订阅地址，无需重新导入 MITM 证书。

**安全提示**：公开仓库中不得存放手机配置、私有订阅、节点账号、MITM 私钥。
