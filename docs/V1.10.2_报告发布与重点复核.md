# V1.10.2 报告发布与人工复核优化

## 为什么 PR 测试成功但没有正式报告
PR 自动测试会在临时目录分析当前已发布的 V1.10 规则，不向 `main` 提交报告。此变更将 PR 产生的完整分析结果保存为可下载的 GitHub Actions Artifact；在合并维护变更后，新版稳定工作流会由 `main` 推送自动触发一次，运行成功后才将分析报告发布到 `reports/v1.10/`。

## 本次审计发现
基于 V1.10 的规则文件进行静态核对，已有 22,019 条规则。CI 先前得到约 1,701 对域名跨策略候选和 82 对 IP 交叉候选；它们不是已确认故障。

从 HOST/HOST-SUFFIX 父子覆盖候选中，额外检出18对“文件中直连规则先于代理规则”的关系，主要包括 SteamCN 与 Steam、中国区腾讯相关规则和小米。该结果依据**文件先后顺序**，并不代表 Quantumult X 开启匹配优化后的运行时策略优先级。分析器在 `priority_audit.md` 单列此类候选，供后续活动日志验证。

## 修改范围
- `scripts/analyze_rules_v1102.py`：增加直连在文件中先出现的覆盖候选摘要。
- `tests/test_rule_analysis_v1102.py`：增加排序、关系和示例的回归测试。
- `.github/workflows/validate-v110.yml`：将 PR 完整规则分析输出保留7天供下载。
- `.github/workflows/update-v110.yml`：分析器、测试及稳定工作流在 main 分支变更时自动执行一次正式聚合和原有安全审计，发布报告；旧版按计划的定时检查继续保留。

## 安全边界
不删除、不调整已发布 `.list`，不改变节点分流，不将证书或私人订阅上传到 GitHub。当前阶段 P1/P2 是人工审查建议，不作为新的发布阻断条件。正式发布仍需沿用既有 V1.10 完整性与风险审计，审计失败时不会更新规则。

## 查看报告
- PR 页面 Checks/Actions 的 Artifacts：`qx-v1102-pr-analysis-<run number>`。
- 合并后的正式更新运行成功时：仓库 `reports/v1.10/priority_audit.md`、`rule_types.md`、`domain_overlap.csv`、`ip_overlap.csv` 和差异报告。
